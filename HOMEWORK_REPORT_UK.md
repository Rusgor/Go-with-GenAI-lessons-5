# Рефакторинг виконаного ДЗ: Error Handling

## Мета

Повторно звірити виконане домашнє завдання з вимогами [README.md](README.md), прибрати ознаки незавершеної роботи та посилити тести для важливої поведінки. Публічні API й основну логіку збережено: реалізації вже відповідали критеріям README, тому рефакторинг був цільовим, без переписування робочих алгоритмів.

## Завдання 0 — multi-package проєкт

### Вимога

Винести логіку калькулятора й аналізатора тексту в окремі пакунки, зробити їх тестованими та передбачувано обробляти помилки через sentinel errors і wrapping (`errors.New`, `fmt.Errorf` з `%w`). `main.go` має з'єднувати пакунки, а не містити бізнес-логіку.

### Реалізація та рефакторинг

- `task0_refactor/internal/calculator` надає `Add`, `Subtract`, `Multiply` і `Divide`. Ділення на нуль повертає помилку, що обгортає `ErrDivisionByZero`; її можна перевірити через `errors.Is`.
- `task0_refactor/internal/textanalyzer` надає `WordCount` і `CharCount`. `WordCount` розбиває текст за пробільними символами та повертає обгорнуту `ErrEmptyText` для порожнього або whitespace-only рядка. `CharCount` обрізає пробіли лише з країв і рахує Unicode-руни, а не байти.
- `task0_refactor/cmd/app/main.go` лишається тонкою точкою входу: демонструє виклики пакетів і перевірку sentinel-помилки через `errors.Is`.
- Прибрано застарілі TODO-коментарі з уже реалізованих функцій — вони більше не описують код як незавершений.
- Тести доповнено перевірками Unicode та кількох видів пробілів у `WordCount`, а також Unicode-рун і обрізання граничних пробілів у `CharCount`.

### Результат

Логіка розділена за відповідальністю, помилки можна програмно розпізнати, а перевірки покривають не лише базові приклади, а й Unicode/whitespace-поведінку.

## Завдання 1 — валідація форми реєстрації

### Вимога

Створити власний тип `ValidationError` і за один виклик повертати всі невалідні поля, не припиняючи перевірку після першої помилки.

### Реалізація та рефакторинг

- `RegistrationForm` містить `Email`, `Password` і `Age`.
- `ValidateRegistration` перевіряє всі поля та накопичує помилки: email не має бути порожнім; пароль має містити щонайменше 8 рун; вік повинен бути в діапазоні `[0, 150]`.
- Якщо є порушення, повертається `*ValidationError` з `Fields []string`; `Error()` формує читабельне повідомлення. Виклик `errors.As` дає змогу отримати структуровані дані.
- Якщо всі поля валідні, функція повертає `nil`.
- Видалено застарілі TODO-підказки з готової реалізації.
- Тест спільної помилки тепер звіряє повний очікуваний список `email`, `password`, `age`, включно з порядком. Додано перевірки допустимих граничних значень віку `0` і `150`.

### Результат

Клієнт одержує повний набір порушень за одну валідацію та може працювати з типізованою помилкою, а не аналізувати лише її текст.

## Завдання 2 — retry-механізм

### Вимога

Реалізувати `Do`, що повторює операцію лише для тимчасових помилок, розпізнаних через `errors.Is(err, ErrTemporary)`, обмежує кількість спроб і повертає обгорнуту фінальну помилку після вичерпання ліміту.

### Реалізація та рефакторинг

- `Do` відхиляє `maxAttempts < 1`, завершується одразу при успіху та не повторює постійні помилки.
- Для тимчасової помилки виконується пауза `backoff` між спробами, але не після останньої спроби.
- Після вичерпання ліміту повертається повідомлення з кількістю спроб і `%w`-обгортанням останньої помилки; отже `errors.Is(err, ErrTemporary)` залишається істинним.
- Видалено застарілу TODO-інструкцію; документований контракт `Do` залишено в коментарях.
- Наявні тести перевіряють успіх, повторні спроби, вичерпання ліміту, збереження sentinel-помилки, відсутність повтору для постійної помилки, некоректну кількість спроб та backoff.

### Результат

Retry не маскує постійні помилки, виконує обмежену кількість спроб і зберігає ланцюжок помилки для перевірки через `errors.Is`.

## Перевірки

Усі команди виконано з кореня модуля після внесення змін:

| Команда | Результат |
| --- | --- |
| `go test ./... -v` | Успішно. Тести всіх пакетів пройшли; прапорець `-failfast` не використовувався. |
| `go build ./...` | Успішно. Усі пакунки зібрано. |
| `go vet ./...` | Успішно. Статичних зауважень не виявлено. |

## Як запустити локально

```bash
go build ./...
go test ./... -v
go vet ./...
```

Не додавайте `-failfast` до запуску тестів, щоб побачити результати всіх перевірок. CI у `.github/workflows/classroom.yml` окремо запускає збірку, тести кожного завдання та `go vet`, друкує логи й підсумок по всіх перевірках, а завершує job помилкою після проходження кроків, якщо будь-який із них неуспішний.

## Підсумок змін

- Усунуто застарілі TODO-позначки з реалізованого коду.
- Посилено перевірки Unicode, whitespace, повноти помилки валідації та граничних значень віку.
- Контракти пакетів, публічні API та існуючий retry-підхід збережено.
- `go test ./... -v`, `go build ./...` і `go vet ./...` завершилися успішно.
